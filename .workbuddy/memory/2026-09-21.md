## 「加了官方分词器后准确度下降」归因（重要结论）

新增文件（用户下载）：`tokenizer.json`(34MB) / `tokenizer_config.json` / `config.json` / `rl_agent_config.json`。
`rl_agent_config.json` 是**真正的 agent 配置**：`encoder = jhu-clsp/mmBERT-base`、head_layers 2、
max_len 1024、head_max_len 256、temperature [1,1,1]、**`max_prefixes: 6`**。
`config.json` 只是**基座编码器**的 stock 配置（`ModernBertForMaskedLM`），没有 scorer/type_emb/act_head。

### 结论：不是准确度下降，而是「从不可判定变成可判定且不达标」

1. **模型卡 expect 三臂全错，且落在无信息先验上**（PRESETS[0]：expect billing/1.84/0.892/0.94）：
   - A 字节兜底：other / 1.0055 / 0.500214 / 0.500252
   - B 官方词表：other / 1.0003 / 0.502918 / 0.497276
   - R 修正▁：other / 0.9994 / 0.499907 / 0.499297
   → `noul` 精确落在 **0.500**、`score` 精确落在 **1.000**（0..2 的中点）= 模型给的是**无信息先验**。
   A 与 B 在模型卡上**无法区分**。"官方词表"没有让任何东西变差，因为**本来就没有信号**。
2. **n=120 同批局面配对检验**（2048 三项指标）：A→B 差值 合法方向 −2.5pp / merge −10.0pp / crowd −6.7pp，
   差的标准误 ±6pp → **全部不显著**。n=30 时看到的 63→73pp 波动同样是噪声。
3. **机制：argmax 在近均匀分布上完全由「prompt 几何偏置」决定，与棋盘内容无关**。实测方向分布：
   - A 字节兜底（700 tok）：up 77/120 = 64%，right 7/120 = 6%
   - B 官方词表 Ġ 编码（310 tok）：right 63/120 = 52.5%，up 29%
   - R 只把空格 token 换成 ▁（219 tok）：**right 117/120 = 97.5%，up 0%**，而此时熵 = **1.0000**、maxP = 0.2505
   → 棋盘完全相同，只改 token 几何，argmax 直方图就翻天覆地。任何 ad-hoc「准确度」都可正可负摆动 10–20pp。
4. **平凡探针也失败**（答案直白写在 state 里："the answer colour is blue"）：A 选 red、B 选 yellow。
   → 决策通道在**两种模式下都没有语义对齐**，主因是 **prompt 模板 / type_emb 注入 / head 读取位置**这类
   config.json 里根本没有、只能靠猜的重建项（`max_prefixes:6` 完全未被建模）。

### 三个已定位的真实缺陷（与准确度下降无因果，但都该修）

| # | 位置 | 问题 | 证据 |
|---|---|---|---|
| 1 | `_bpe_word()` line 425-444 | 用 **GPT-2 byte2uni** 约定，空格→`Ġ`(id 241753) | tokenizer.json 声明 `normalizer: Replace(" "→"▁")` + `pre_tokenizer: Metaspace(▁)`；词表 ▁ 条目 **125261** vs Ġ 条目 **1**。实测提示 133 tok 中 45 个是 Ġ、含 ▁ 的 0 个；正确编码 110 tok（▁game/▁board/▁empty） |
| 2 | `DEFAULT_CFG["attention"] = "global"` line 85 | 与 config.json 的 `layer_types` 冲突 | config.json：每 3 层 1 层 full + sliding(local_attention 128)；`local_radius:64` 恰好 = 128//2 ✓，应设 `alternating3` |
| 3 | `DEFAULT_CFG["rope_theta"] = 10000` line 83 | 官方 **160000** | 实测 θ=1.6e5 时 maxP 0.26→**0.82**、熵 0.99→**0.35**、合法方向 73.3→53.3、merge 50→36.7 → **「自信但错误」**，这才是真会出现「准确度明显下降」观感的开关 |

### 工具自身的误导（放大了困惑）

- `Verifier.run()` line 1312 / 1324：`模型卡示例语义对比` 硬编码 `BLOCKED`，verdict 字符串硬编码
  "语义精度：BLOCKED —— 缺官方 256k 词表 tokenizer"，**不读 `tok.faithful`**。于是徽章显示"真实词表"、
  报告仍写 BLOCKED，自相矛盾。且缺一个**通道自检探针**（平凡可判定问题），导致通道错位长期未被发现。
- 验证报告的状态机应改为：`faithful=False` → BLOCKED；`faithful=True` → 跑探针，按命中率给 PASS/WARN/FAIL。
